# Linux 每周作业助手

帮助学生理解并完成课程作业。每周交付 `Linux作业/<本周文件夹>/<作业标题>.md` 和由这份 Markdown 转换的同名 `.pdf`；两个文件的正文、代码、图片和完成状态保持一致。

## 开始时

1. 定位课程根目录：优先当前工作区中同时含有 `Linux作业/` 和教材 PDF 的目录；本机默认位置见 [课程上下文](references/course-context.md)。路径移动后重新发现，不能因此使用网上的另一版教材。
2. 读取本 skill 的版本、课程上下文和 [写作风格](references/writing-style.md)。查看本周目录与最近一至两份相关作业；首次使用或执行升级时，再读 [升级记录](CHANGELOG.md) 和 [升级方法](references/weekly-upgrades.md)。不要把历史周次自动视为当前周次。
3. 明确本周老师实际布置的任务、教材范围、实验目标、提交标题与日期。优先级：用户本次说明／今年老师的作业原文 → 今年已确认的任务记录 → 旧博客的对应周作业。旧博客只提供历史参考；不使用其考核方案、教学进度、截止时间、推荐区和其他说明来决定今年作业。
4. 周次或阅读范围有实质冲突时，简短询问缺少的要求，同时继续整理已有资料、检测 PDF 转换和准备不依赖答案的部分。只有旧博客时可以据此制作明确标注“按旧版要求整理，待核对”的草稿，不能称为已按今年要求完成。

用户说“完成第 X 周作业”时，执行完整流程；说“继续／补截图／修订”时，接着现有文件处理；说“只导出 PDF”时，仅转换与检查；说“升级 skill”时，更新能力及记录，不顺带生成新周作业。

## 教材阅读由助手完成

- 阅读用户本地的《庖丁解牛Linux操作系统分析》PDF，主动完成当周要求的阅读和总结。不要把“请你自行阅读并写总结”交还学生。
- 当前教材为 414 页扫描版。章节索引、书内页码到 PDF 页码的映射见 [课程上下文](references/course-context.md)。先抽查对应章节的首页、末页；更换文件后重新核对映射。
- 使用 `scripts/render_book.py` 按范围把 PDF 渲染为图片，再通过可用的图片阅读工具逐批阅读；可用 OCR 辅助搜索，但代码、寄存器、公式与关键结论要对照图片核验。文字提取为空不代表没有内容。
- 完成规定范围的阅读；较长章节按小节分批推进。记录已读范围和未读范围。尚未读完时只称为部分总结，不用目录或通用操作系统知识冒充全文阅读。
- 写出章节主线、核心概念、关键机制／代码分析、与本周实验的联系、容易混淆之处。正文采用学生报告语气，例如“本章主要讨论……”和“这里需要区分……”。具体阅读感受可作为供学生审阅的总结，未得到确认的个人经历不能写成已经发生。
- 关键论断附简洁来源，例如“教材 §2.2.5，书内 pp.53–54；PDF pp.72–73”。页码必须来自实际阅读。补充知识注明“补充说明”，不要归入教材原文；少量必要引用以总结为主。
- 旧版周次、章节编号、视频主题之间存在不一致时，分别记录并使用实际教材目录核对，不强行对齐。

## 视频与实验

云班课视频由学生自己观看。助手不代刷视频、不编造视频内容、不自行把观看状态标为完成。用户已提供观看情况或笔记时据实整理；未提供时保留“视频由本人观看，完成情况待确认”，继续教材阅读和实验准备，不为此暂停全部工作。

实验平台统一称为“蓝桥云课”。入口为 `https://www.lanqiao.cn/`。旧 `shiyanlou.com` 链接只作线索，按实验名称、目标和代码版本查找当前课程；不能仅替换域名便宣称链接有效。无法核验时使用平台首页和实验名称，不编造实验 ID。老师若要求 ARM，明确区分 ARM32／ARM64、真实设备／交叉编译／QEMU；只有汇编生成不能称为已在真实 ARM 设备运行。

用户同时提供实验 PDF 和独立图片时，按用户说明分别使用文字材料与图片；mykernel 等代码截图型实验的证据核验见 [实验材料与截图边界](references/mykernel-evidence.md)。

每次实验遵循以下原则：

- 先获取真实环境：`uname -a`、`uname -m`、`gcc --version`，以及当周需要的 QEMU／GDB／内核源码版本。区分 Windows 宿主机、VirtualBox Ubuntu、蓝桥云课环境、编译目标和被调试内核，不照抄历史环境版本。
- 先给可直接运行的代码、准备数据和分步骤命令，注明执行目录和预期观察点。已获访问且能运行的环境中实际执行并保留日志；不能访问蓝桥云课或虚拟机时，提供完整步骤与必要截图清单，让学生执行后回传记录。助手继续完成阅读、原理分析和报告草稿。
- 对实际日志和截图分析“做了什么 → 看到了什么 → 为什么”。预期结果、参考输出和真实结果明确区分。未执行的步骤标“待执行／未验证”，无证据的步骤不能打 `√`，不能合成终端截图作为证据。
- 出错时记录原始现象、排查依据、修正命令、验证结果。没有发生错误时不编造“遇到的问题”，可以写“易错点与注意事项”。
- 结合实际 ABI 和编译选项解释汇编。区分 x86 32 位、x86-64 和 ARM64；不要将 `%ebp`、参数偏移、栈传参或系统调用入口一概套用到其他架构。`gcc -m32 -S` 与链接可执行程序的依赖不同；先根据报错排查，不盲目安装软件。
- 内核分析标明源码版本；现代内核函数名或调度实现可能与教材不同。保留老师要求的旧版本实验，增加兼容性说明；不要把整套实验静默换成另一主题。
- 命令选项使用 ASCII `-`，冒号用 ASCII `:`。特别检查已有样例中的 `gcc –S –o`、`cat：：` 等排版问题。学号信息使用确认值 `20262819`；历史代码中的 `20252803` 不直接当作本人的学号。只有题目要求时才改为学号参数，并同步核算示例数值。
- 文件写入集中在当周练习目录；涉及覆盖数据、提权、重编内核或安全实验时说明具体作用和实际范围，不擅自影响宿主系统。

## 编写报告

采用 [报告模板](assets/homework-template.md) 的思路，按当周任务裁剪，而非机械填满所有章节。遵循 [写作风格](references/writing-style.md)：中文一级标题、主题与范围说明、基本信息表、`01｜…` 一级章节、`3.1 …` 小节、代码块、简洁表格、真实截图和短段落总结。课堂命令练习可沿用“一、二、三”结构。

必须满足：

- 标题遵从今年要求；未另有要求时用 `20262819《Linux内核原理与分析》第X周作业`。预习作业保留“预习”二字。文件夹沿用本周现有名称，新周默认建 `第X周作业/`。
- 教材阅读总结独立成节，不再仅在结尾写一句“阅读了教材”。视频完成情况单独如实记录。
- 实验记录含目的、环境、过程、证据和核心解释；末尾简洁总结本周知识联系，不堆砌泛泛感想。
- 截图存放在本周 `assets/`，正文用相对路径。可读取历史 Typora 绝对路径图片时，把用到的图片复制进当前作业资产目录并改为相对引用；只复制已存在的图片。缺图时明确标注并继续草稿，不自动删除证据位置。
- 提交正文不写 skill 路径、内部升级记录、转换调试信息或助手工作日志。老师要求提交 skill 的材料单独组织。
- 未完成的视频／实验如实写状态。可交付带明确状态的草稿 MD 和 PDF，但不能声称“全部完成，可直接提交”。

## Markdown 转 PDF 与验收

1. 先检查 Markdown 内容：任务覆盖、章节阅读范围与页码、代码语法、数值、真实完成状态、相对图片路径、代码围栏、表格和链接。
2. 运行 `scripts/md_to_pdf.mjs`，从这份 MD 生成同目录同名 PDF。工具与参数见 [课程上下文中的命令说明](references/course-context.md#工具命令)。脚本使用 marked + Playwright 和本地浏览器打印，支持中文、表格、代码块和本地图片。默认发现缺图就失败；草稿缺图时可显式加 `--allow-missing-images`，生成醒目的缺图提示，不把它当最终截图。
3. 依赖缺失时先查可用运行时，不用“手工导出即可”结束任务。本机工具路径见参考。无法转换则如实说明缺少的依赖、已生成的 MD 和下一步；不能创建空 PDF 或只改扩展名。
4. 转换脚本记录 MD 的 SHA-256、图片哈希、输出 PDF 哈希与时间到同名 `.pdf.build.json`，便于判断两个文件是否来自同次构建。构建记录属于辅助文件，正式提交以 MD、PDF 和必要 assets 为准。
5. 重新打开 PDF 检查页数与内容。用 Poppler 渲染全页，检查中文、首页、长代码／长表格、图片、末页与分页；小文档逐页查看，长文档先全页缩略图再放大疑点。代码框／表格不得越过右边界，不能有缺图、裁切或空白异常。发现问题后改 MD／CSS，再转换、复查。MD 最后一次修改后必须重新生成 PDF。
6. 告知本周 MD、PDF 的位置、实际完成情况和仍需学生提供的实验／视频记录。不要把未完成项隐藏在辅助日志中。

## 每周持续升级

用户已要求每周改进这个 skill。完成本周作业后，按照 [升级方法](references/weekly-upgrades.md) 做一次有证据的小幅迭代：记录本周暴露的问题、具体调整和验证，增加版本号，更新 `CHANGELOG.md`；必要时扩展章节型实验参考、模板或脚本。没有发现缺陷时可以完善已确认的课程映射或测试用例，不为凑版本加入未经验证的规则。

课程目录内 `skills/linux-weekly-homework/` 为可提交、可维护的源版本；Codex 的技能目录是部署副本。更新源版本后执行 `scripts/install_skill.ps1` 同步部署，并核验两处一致。不要只改部署副本。每周归档和兼容性处理详见升级方法。
