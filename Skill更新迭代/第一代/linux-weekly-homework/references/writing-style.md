# 作业写作风格

## 从已有三份 MD 提炼的习惯

- 中文标题与基本信息表放在开头；常规周作业增加主题、学习范围，主章节用 `01｜…`，实验小节用 `2.1 …`，分隔线连接大章节。
- 简洁第一人称学生报告语气，讲清知识联系。每个命令／代码块紧接其作用与观察点，不写成堆叠命令的清单。
- 实验依次包含目的、环境、代码／命令、实际截图、分析。关键关系使用短表格或文字流程，截图前可用“实践截图”“我的实验记录”等自然提示。
- 总结通常两至三段，概括学到什么、概念之间的联系和仍需巩固什么。不要夸大掌握程度或虚构亲历感受。
- 命令练习允许“一、学习内容”“二、实践准备”这类中文序号，与已有课堂测试相符。报告骨架可随任务变化。

## 保留风格，补上原样本的不足

第二周样本“阅读教材”只有进度表和结尾描述。今后增加独立阅读总结，并将主线和实验连接起来。可采用：

```markdown
## 02｜教材阅读与理解

### 2.1 本章主线

本章主要讨论……。其中……是理解后续实验的基础。

### 2.2 关键概念与机制

| 概念 | 我的理解 | 与本周实验的联系 |
| --- | --- | --- |
| 实际读到的概念 | 根据原文总结 | 根据任务说明 |

关键步骤和代码在必要处展开，不把所有内容压缩成表格。

来源：教材 §对应小节，书内 pp.实际页码；PDF pp.实际页码。
```

此例只指导结构，写作时替换说明文本，不留占位词。

## 实验分析的尺度

- 区分理论推导和观察结果。例如函数表达式的完整计算结果，不等于 Shell 的 `$?`：常见 Unix 退出状态只保留低8位。是否讨论这一点由实际任务决定。
- “参考汇编”注明架构与选项；结合学生实际 `.s` 文件解释，不将参考指令当作其编译器的真实输出。
- 对材料的错别字、选项符号、参数值进行复核；修正后的写法可直接用于新作业，不把旧错误复制成风格。
- 遇到不同版本时解释差异，并保留老师要求和当前实验事实，不将二者混写。

## 图片与交付

使用 `![函数调用汇编结果](assets/函数调用汇编结果.png)` 这类含义明确的相对引用。原图命名可以保留，但替代文字应解释截图内容。不要让提交文件依赖个人 AppData 路径。

没有实际截图时用正文“本步骤待执行，需记录……”，不要写一个不存在的图片链接伪装完成。最终 PDF 要包含已有真实图片，不以网页输出或原有 PDF 冒充从新 MD 导出的文件。
