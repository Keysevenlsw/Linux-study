# 系统调用内核调试要点

用于 QEMU/GDB 内核实验，尤其是32位 x86 的 `system_call → iret` 跟踪。下面的调用号、符号和槽位示例来自第六周 Linux 3.18.6；其他架构和版本先核对对应源码，不直接套用。仍按“一步操作 → 截图 → 核对后下一步”指导，不一次发送整套命令。

## 启动阶段与断点位置

- QEMU 使用 `-s -S` 后，首次连接可能停在 BIOS 地址 `0x0000fff0`。此时符号地址可查询，不代表内核已经装载到运行地址；连续的 `add %al,(%eax)` 可能只是零字节解码。先断在 `start_kernel` 并命中，再查看入口代码，不能凭这次反汇编认定入口损坏或立即重编内核。
- 需要在任何软件压栈前查看硬件返回现场时，用 `tbreak *system_call if $eax == 4` 精确断在入口第一条指令。源码函数断点可能经过序言，读取栈布局前先核对当前指令。
- 以实际加载的 `vmlinux` 和对应 `bzImage` 配对；地址和行号从本次符号与反汇编取得，不把报告里的地址写死到下一次命令。

## 有输出但未命中 system_call

不能直接断定系统调用没有发生，也不能把用户态 GDB 当成内核调试。32位程序可能经 `sysenter` 等另一入口进入内核。

1. 在内核 `sys_write` 处设置断点，再触发一次可辨认的输出。
2. 核对当前确实位于函数第一条指令，尚未压入函数序言数据，再读取栈顶返回地址：

   ```gdb
   x/i $eip
   x/wx $esp
   info symbol *(unsigned int *)$esp
   info args
   ```

3. 返回地址若属于 `sysenter_after_call`，说明这次输出采用了快速入口；普通库函数的实际入口取决于运行环境，不能保证一定使用 `int $0x80`。
4. 老师明确要求 `system_call → iret` 时，在用户程序中显式使用 `int $0x80` 触发同一系统调用，不把整项作业替换成 `sysenter` 分析。

GDB 对汇编入口的回溯可能显示 `<signal handler called>` 或不可访问内存；这不能单独证明用户程序收到了信号。根据指令、寄存器、保存现场和源码判断，不补造完整调用栈。指针按有符号整数显示为负数时，先转十六进制并核对内存，不能直接宣布参数非法。

## 构造可控调用和独立镜像

第六周使用 MenuOS 的 `test.c`：在 `main()` 前添加处理函数，在 `ExecuteMenu()` 前注册。先查看本次实际注册语句和构建规则，不凭历史片段覆盖整个文件。用户程序是调试触发器，不必为了触发系统调用重编内核。

示例处理函数中的关键部分：

```c
const char msg[] = "Hello syscall\n";
int ret;
__asm__ volatile (
    "int $0x80"
    : "=a" (ret)
    : "0" (4), "b" (1), "c" (msg),
      "d" ((unsigned int)(sizeof(msg) - 1))
    : "memory", "cc"
);
```

请求长度为14，不包含末尾空字符；用 `printf` 显示 `ret` 是后续另一项用户态操作，不把它混成正在跟踪的调用。通过 `gcc -m32 -static -g` 编译并核对实际结果。最小 initramfs 使用静态程序时不必另放动态解释器和共享库。

课程第六周的 `make rootfs` 还会自动启动没有 `-s -S` 的 QEMU。需要调试时单独编译、以 `/init` 打包到新命名镜像，再明确使用该镜像启动，保留原镜像。替换镜像前先断开旧调试连接并关闭旧 QEMU，避免连接错实例或端口冲突。不能把本周自制镜像或源代码修改视为全新云环境的预置文件。

## 保存现场、分派和返回值

- 在入口第一条指令处，普通用户态到内核态的32位 `int $0x80` 返回现场按地址递增为 EIP、CS、EFLAGS、用户 ESP、SS。保存栈位置和用户 EIP，后续核对同一次返回。
- 入口保存原始调用号并执行 `SAVE_ALL` 后，按本次配置解释完整现场。Linux 3.18.6 示例中保存的 EAX 槽位偏移24字节，orig_eax 偏移44字节，用户 EIP 偏移48字节；GS 槽位可能是占位值，不一概解释为实际 GS。
- 在 `syscall_call` 验证间接调用与表项。i386 下表项占4字节，第4号条目相对 `sys_call_table` 偏移16字节，应与本次 `sys_write` 地址一致。
- `sys_write` / `SyS_write` 可以是系统调用宏生成的相关符号。先核对地址、源码和参数，不按名称差异误判为另一调用。
- 从写入函数 `finish` 后仍在内核态。先核对 `eax` 返回值，再单步观察 `syscall_after_call` 将它写入保存现场的 EAX 槽位；`iret` 本身不负责生成系统调用返回值。

## 根据实际工作标志跟踪退出

- `syscall_exit` 检查工作标志；无待处理工作时恢复寄存器，有工作时先进入处理分支。不要提前要求所有截图都必须出现直接恢复路径。
- 该版本的 `_TIF_NEED_RESCHED = 1 << 3 = 0x8`。第六周实际捕获到此值；未来以本次读取和对应版本定义为准，不能把0x8设为成功条件。
- 进入 `syscall_exit_work` 不等于执行了 `syscall_trace_leave()`。观察 `_TIF_WORK_SYSCALL_EXIT` 检查后的实际跳转；第六周转到 `work_pending`，在 `work_resched` 调用 `schedule()`。
- 调度函数返回后会重新检查工作。调用 `schedule()` 只能证明执行了调度处理，未观察任务选择或切换时，不声称切换到了某个进程。信号、通知、跟踪等没有实测的分支在流程图中注明是条件路径。

## 捕获同一次 iret 并闭合证据

`irq_return` 可被不同任务及不同返回路径使用，不能把任意一次命中当成目标调用返回。示例中先在入口保存：

```gdb
set $entry_sp = $esp
set $user_pc = *(unsigned int *)$esp
```

再用条件定位本次普通32位返回：

```gdb
tbreak *irq_return if $esp == $entry_sp && *(unsigned int *)$esp == $user_pc
continue
```

命中后重新确认当前是 `iret`、五项返回现场与入口一致、EAX为真实返回值。单步执行后核对 EIP、ESP、CS、SS、EFLAGS，以及 `$eip == $user_pc`。内核和用户段选择子的具体值依构建而变；通过 CS 低两位判断权限级，不把 `0x60` / `0x73` 当成所有系统的固定值。

最后继续用户程序，记录最终输出和返回值。流程图要区分硬件保存现场、软件保存寄存器、内核函数普通返回和 `iret` 跨权限级返回，并保留返回前工作处理及重新检查的分支。使用能在 Markdown/PDF 中直接显示的图片，不能只交无法被转换器渲染的 Mermaid 源码。关键证据被窗口遮挡时只补读缺少部分，不为形式重做已经验证的实验。
